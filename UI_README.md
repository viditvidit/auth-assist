# OAuth Guide UI

A Next.js + TypeScript UI prototype using Tailwind CSS and shadcn Base UI (Nova), with agent configuration, bounded research, and evidence-backed guide generation.

## Run

```sh
npm ci
npm run dev
```

Open the local URL printed by Next.js. No API keys or environment variables are required for the current UI or static example.

## Agent foundation — Phase 1

- `lib/agent/model.ts` exports the server-only `createResearchModel()` factory using LangChain's Gemini adapter. Set `GOOGLE_API_KEY` and `GEMINI_MODEL` in `.env.local` or Vercel's environment settings. See `.env.example`.
- Configuration is checked only when the factory is called. Errors name missing variables without printing their values. The factory does not invoke the model or check remote availability; authentication, model access, and network failures can only be confirmed on a future invocation.
- `lib/agent/schema.ts` exports the research input, claim, source, and guide schemas with inferred TypeScript types. Existing UI scenario types reuse the research input contract.
- Unknown effort and approval durations have `status: 'unknown'`, `value: null`, and an explanation. Estimates and documented durations carry their basis and source references.
- Claims distinguish documented, estimated, and uncertain evidence. Source records distinguish search excerpts from page text. Phase 3 checks source references and reviews factual support; schema validation alone does not verify evidence.

The GitHub research-to-guide flow has been live-checked after fixing Gemini duration-schema compatibility. Phases 2 and 3 provide the workflows below. The streaming endpoint and persistence remain later phases.

## Research — Phase 2

`lib/agent/research.ts` exports `researchProvider(input, { signal?, onActivity? })`. Each invocation creates its own tools and evidence store. The result contains preliminary findings, unknowns, collected sources, and a status of `researched`, `partial`, or `clarification_required`. Findings are not a verified or finished setup guide.

Agent instructions and tool descriptions live in `lib/agent/prompts/*.md`. The server-only loader reads them from the project root; Next.js tracing includes these files in deployed functions. `research-tools.ts` handles tool limits and evidence collection, while `search-web.ts` and `read-page.ts` handle retrieval. Research and guide schemas live together in `schema.ts`.

To try it locally, use Node.js 22.9+ (Node.js 24 is used for development), copy `.env.example` to `.env.local`, and fill in `GOOGLE_API_KEY`, `GEMINI_MODEL`, and `PERPLEXITY_API_KEY`. Choose a Gemini model supporting tool calling and structured output. Then run:

```sh
npm run research -- "GitHub" "Read repository issues" "My team"
```

This command makes real, potentially billable Gemini and Perplexity requests. Activity goes to stderr and the JSON result goes to stdout. Ctrl+C requests cancellation. A partial result exits with code 1 while retaining evidence; a clarification response includes a question to resolve before rerunning. To save just the JSON, invoke the script directly without npm's banner:

```sh
node --conditions=react-server --env-file-if-exists=.env.local --import tsx scripts/research.ts "GitHub" "Read repository issues" "My team" > /tmp/auth-assist-research.json
```

The CLI uses the `react-server` condition to resolve Next.js's `server-only` marker outside Next.js. There is no public research API or UI connection yet. The installed LangChain and provider credentials are used only when you run research.

Limits: four searches, six page reads, a 90-second run budget, 15 seconds per search, 12 seconds per page including redirects, up to three redirects, 1 MB search responses, and 2 MB page responses. Retained excerpts are capped at 4,000 characters per search result and 16,000 per page. Pages are fetched using validated, pinned public IP addresses. HTML and plain text are supported; PDFs, login-required pages, and JavaScript rendering are not. Search excerpts and page text remain distinct evidence types. Sources are not automatically fact-checked in this phase.

Missing configuration fails before research starts. Access errors, budgets, malformed output, and network failures produce gaps or partial results. The GitHub flow has been live-checked; browser checks have not been run.

## Guide generation — Phase 3

`lib/agent/generate-guide.ts` exports `generateGuide(input, options)`, using the same scenario, optional cancellation signal, and research activity callback as Phase 2. It runs research, generates a structured draft, and reviews the claims against the collected evidence. The original scenario and source records are attached by code, never generated by the model.

```sh
npm run guide -- "GitHub" "Read repository issues" "My team"
```

This makes real Gemini and Perplexity calls using the same three environment variables. Results contain a `complete` or `partial` guide, preliminary research, and the model's review verdicts. Ambiguous providers return `clarification_required` before guide generation. Runs with no evidence, failed generation/review, cancellation, or timeouts return an explicit `error`, retaining any research result. Partial and error results exit with code 1.

The full run has a 120-second deadline (including the research stage's maximum 90 seconds). There is at most one structured-output repair shared by draft generation and evidence review. Missing or invalid source IDs are removed and affected claims are marked uncertain. Missing/duplicate review checks also leave claims uncertain. Unsupported timelines become unknown rather than retaining speculative durations. Research gaps are reassessed against later evidence; unresolved caveats and review contradictions remain visible. Completeness depends on material gaps affecting the setup path, not every unknown duration or optional detail.

Generation, review, and repair instructions are separate Markdown files. Review is a model-assisted evidence check, not proof of correctness or a real provider setup attempt. The latest GitHub team issue-reading run completed with 4 steps, 17 source records (including 2 page reads), and 11 review checks. Provider review was not required, its wait was not applicable, and organization approval was conditional. These are model-reviewed documentation conclusions, not a tested provider setup. The web UI still uses local messages and static examples; it is not connected until Phase 4.

## Screens

- `/`: enter an app name or website, an optional use case, and an audience.
- `/workspace`: form context is passed through URL query parameters. Submitting messages only appends user messages locally.
- `/workspace?example=true`: a labelled, fixed example with expandable activity, guide sections, and a working sample checklist.

Desktop uses conversation and guide columns; smaller screens use Chat/Guide tabs. Enter sends a message and Shift+Enter adds a newline. Blank messages cannot be sent.

## Boundaries

The UI is not connected to the model factory. There is no UI-facing research endpoint, database, authentication, or generated UI response. Example content is generic and contains no verified provider requirements or citations. Messages, drafts, and checklist changes live in React state and reset on refresh. Form context is visible in the URL; do not enter credentials.

The example content is in `lib/example.ts`; the setup form, workspace, conversation panel, and guide preview are separate components. The composer follows the shadcn AI Elements Input Group composition. Existing repository configuration and pre-existing deletions were preserved.

## Validation

```sh
npm run typecheck
```

TypeScript checking and seven targeted schema and evidence regression checks passed:

```sh
node --import tsx --test tests/guide-schema.test.ts tests/guide-evidence.test.ts
```

The duration schema uses an object with local cross-field validation: Gemini's adapter drops `oneOf`, which previously caused invalid duration output. Repair validation now inspects raw tool arguments when the adapter returns `parsed: null`, preserving field-level errors.

Live Gemini draft generation and the full Gemini/Perplexity GitHub guide flow were checked. Full lint and browser automation were not run. Visual and browser interaction verification remain outstanding.

### Approval applicability and targeted follow-up

Guides now distinguish provider review, organization approval, and marketplace listing using
`required`, `not_required`, `conditional`, or `unknown`, with evidence for each conclusion.
`approvalWait` refers only to provider review and supports `not_applicable` (null value) when
review is supported as not required. Other unknown durations remain explicitly unknown.

Research reserves capacity for one follow-up when questions remain or only excerpts were
collected. It reuses the same sources, four-search/six-read counters, and 90-second deadline;
it does not receive a new budget. Follow-up failures preserve initial findings. Prompts prioritize
full official pages and allow labelled secondary experiences for practical gaps. Page selection
and gap assessment remain model judgments, not guarantees that every question is resolved.

Live verification exposed excerpt-only research and contradictory no-review/unknown-wait output. Research now attempts up to two discovered pages when the model skips page reads, sharing the existing budget. Evidence review reassesses all caveats, and a validated no-review conclusion determines the not-applicable wait. The rerun passed, along with TypeScript and seven targeted regression checks.
